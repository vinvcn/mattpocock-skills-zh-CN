# 工作流（术语落地 / 单文件 / 仓库刷新 / 同步记录）

命令默认在 `[REPO_DIR]` 执行。

## 1. 术语决定与落地（四步）

1. **批准**：维护者把术语登入术语表的「已决定的翻译」区并填「决定于」，请求行保留在请求区。
2. **落地**：开分支，按已决定的译法替换仓库中的字面出现位置（大小写不敏感匹配），只改与该术语相关的出现位置；
   `dsh-plugin/skills/` 是构建产物（gitignored，由 `dsh-plugin/scripts/copy-skills.mjs` 从 `skills/` 生成），**不要手改**，源头修复后随插件构建自动同步。
3. **更新术语表**：把请求行状态改为 `applied`（应用 PR 合并后生效），保留来源引用与历史行。
4. **提交 PR**：按 `CONTRIBUTING.md` 的 PR 检查清单执行（先 `git add` 再运行脚本）；PR 描述链接术语表条目与相关 issue；除非明确要关闭该 issue，不要用会自动关闭它的关键字。

## 2. 单文件（8 步）

1. 确认文件路径和文件类型。
2. 归类：可翻译的自然语言 / 混合内容 / config-metadata / 不可翻译。
3. 翻译前先保护行为关键片段。
4. 只翻自然语言文本。
5. 原样恢复被保护的片段。
6. 检查命令、代码块、路径、URL、identifiers、frontmatter keys 未变。
7. 检查本地化后的安装命令使用 `vinvcn/mattpocock-skills-zh-CN`。
8. 返回译文或 patch，并附全部复核标记。

## 3. 仓库刷新（10 步）

1. 把上游当内容来源，而不是 Git 历史。
2. 找出新增、变更和移除的内容文件。
3. 翻译新增和变更的、含说明性文字的文件。
4. 仅当不可翻译的支持文件属于本次刷新范围时，才复制或保留。
5. 保持本地化仓库的 README 定位和安装路径不变。
6. 按 `validation.md` 完成结构、完整性、索引与行为关键内容检查。
7. 在 `SYNC.md` 同步记录中追加一条简短条目。
8. 在 `README.md` 记录本次验证结果、翻译执行者和翻译策略摘要。
9. 把有歧义的文件、被移除的文件或有风险的转换打复核标记，交维护者审查。
10. 总结：已翻译 / 复制或保留 / 移除 / 跳过 / 验证结果 / 复核标记。

## 4. SYNC.md 条目规范

每次上游刷新都新增一条短文，包含：

- 刷新日期，`YYYY-MM-DD`；
- 上游来源 revision，通常写作 `mattpocock/skills@<short-sha>`；
- 本地同步 commit（已存在则填；否则先写一句待定说明，commit 后替换，**不留「待定」交付**）；
- 一句话描述本次可见的内容变更。

```text
- 2026-05-09：已同步上游 `mattpocock/skills@733d312`，本地 commit `c9fe120`。为 `prototype` 和 `in-progress` 内容新增中文翻译，并刷新公开 skill 索引。
```
